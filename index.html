About

Cloud security and identity, run as operations

I am a Cloud Security Engineer and Identity & Access Administrator. Day to day I administer the full stack: Entra ID, Azure, Intune, SharePoint governance, Atlassian access, and 1Password — plus Conditional Access, PIM, and joiner / mover / leaver. I also write the code (Python, Django, Microsoft Graph API, Logic Apps) that automates access reviews and enforces least privilege at scale.

At Hunt&Hackett I rolled out enterprise-wide Zero Trust with Conditional Access, PIM, and Entra ID Governance, built a custom IAM platform that cut access-review effort by 25%, and automated audit evidence so reviews no longer depend on screenshots.

How I support audits
  • ISO 27001 — identity-log evidence packs instead of screenshot hunts
  • SOC 2 — access-review evidence collected from the source systems
  • Least-privilege and lifecycle controls that auditors can actually trace

ExitScan

Leaver access and orphaned accounts

production
Problem

People left, but cloud accounts and downstream app access often stayed behind — orphaned identities that audits and attackers both find.

Built

Offboarding automation that detects orphaned cloud accounts and revokes access across downstream apps after departure.

Result

Leaver access is revoked as a process, not a hope — fewer leftover accounts after someone has already gone.

Offboarding Entra ID Cloud IAM
